# 压缩会话读取

## 结构与边界

`RolloutReader.swift` 统一识别 `.jsonl` 和 `.jsonl.zst`。只读文件句柄流式解码，使用 `Vendor/Zstd` 的官方解码器，扫描期间不生成解压文件、不改源日志。

- 解码窗口最多 128 MiB，单文件解码输出最多 8 GiB；损坏、截断或超过上限的记录失败，不作为完整会话或部分成本接受。
- Continuity 预览只保留 512 KiB 头部与 1 MiB 尾部。压缩文件需要完整顺序解码来取得尾部，但不保留完整输出。服务按文件大小和修改时间缓存解析后的会话摘要。
- 本地成本仅解析会话元数据、模型上下文及 token_count，按结构化事件身份合并压缩历史、继续写入的普通日志及归档副本。不能仅按同名文件跳过压缩历史。
- 会话盘点按会话 ID 合并；普通同名副本优先用于当前预览。子代理／exec／无用户消息记录仍不计作用户会话。
- 新发现的压缩历史不传入“当前账号新建会话”观察集合；已有可靠归属保持原值，无证据的仍未知。不迁移或重写已有归属。
- 可读导出直接流式读取；完整备份仅在本次导出自己的暂存目录写出解码后的 `.jsonl`，再沿用 v1 manifest、校验和及导入流程。源 `.zst` 保持原样。导入冲突检查也识别压缩来源。
- 压缩历史不会被本次改动接入实时活动激活逻辑，避免回放历史任务。Hook 接入保持屏蔽。

## 依赖

macOS Compression 标准接口不支持 Zstandard。应用内置官方 decoder-only v1.5.7，固定提交与维护检查见 `Vendor/Zstd/README.md`；生产不依赖 Homebrew、命令行 zstd、网络下载或全局安装。BSD 许可随 App 的 ThirdPartyNotices 打包。

## 验证入口

- `scripts/test.sh`：先编译同一份 C 解码器，检查未知内容长度、多 frame、截断／损坏、输出限制、长行、头尾保留、只读来源、压缩成本合并、内部线程、导出兼容与连续性。
- `CONTINUITY_BENCHMARK=1` 运行 ContinuityTests 编译产物可只读核对真实文件数量及分类，输出仅包含汇总计数与耗时。
